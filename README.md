# Evaluating Large Language Model based Personal Information Extraction and Countermeasures

This is the code for evaluating personal profile extraction based on LLMs and countermeasures. Please see our USENIX Security'25 paper [here](https://arxiv.org/abs/2408.07291).

Note: the up-to-date artifact of the original paper is [here](https://zenodo.org/records/14737200).

This repository extends the original codebase with a **US Senator dataset** and additional infrastructure for running experiments via the Groq API (no GPU required).

---

## Datasets

### Original datasets (paper)

The synthetic, celebrity, physician, professor, and court datasets are from the original paper. Download them from [Zenodo](https://zenodo.org/records/14737200) and place them under `./data/`.

- `./data/synthetic/` — synthetic profiles generated by GPT-4 in HTML format
- `labels.json` in each folder contains ground-truth labels

The professor, celebrity, and physician datasets are shared per request — contact the original authors if interested.

### Senator dataset (this extension)

100 US Senator HTML profiles scraped from official Senate websites, stored in `./data/senator/`. This dataset supports 7 information categories:

| Category | Description |
|---|---|
| `name` | Full name |
| `birthdate` | Date / year of birth |
| `gender` | Gender (inferred from pronouns) |
| `race_ethnicity` | Race or ethnicity |
| `committee_roles` | Senate committee memberships |
| `religion` | Religious affiliation |
| `education` | Degree(s) and institution(s) |

**Data layout:**

```
data/senator/
├── <First_Last_ST>.html      # 100 senator profile HTML files
├── icl/                      # 5 held-out profiles for few-shot ICL examples
├── labels.json               # Ground-truth labels
└── info_categories.txt       # One category name per line
external_data/ground_truth/
├── senate_ground_truth.csv               # Compiled ground truth
├── senate_ground_truth_updated_manual.csv
├── committee-membership-current.yaml     # YAML from unitedstates/congress
├── committees-current.yaml
└── pew_religion.csv                      # Pew Research religious affiliation data
```

## Setup

### Environment

Create the conda environment from `./PIE_environment.yml`:

```bash
conda env create -f PIE_environment.yml
conda activate pie
```

For the baseline extractors (`run_baselines.py`), also install:

```bash
pip install spacy transformers
python -m spacy download en_core_web_sm
```

### API keys

Copy the example configs and fill in your keys:

```bash
cp .env.example .env
cp configs/model_configs/groq_config.json configs/model_configs/groq_config.json.bak
```

For API-based models (GPT, Gemini, Groq), set your API key(s) in the corresponding `./configs/model_configs/<provider>_config.json`. For open-source models (LLaMA via HuggingFace), apply for access following the model provider's guidelines.

## Running experiments

### Original paper experiments

Use `run.py` (which calls `main.py`) to reproduce experiments from the paper:

```bash
python run.py
```

Edit `run.py` to select the model, dataset, prompt type, defense, and ICL settings. See inline comments for options.

### Senator dataset — LLM extraction

Use `run_senator_extraction.py` to run the senator extraction matrix with Groq/Llama:

```bash
# Pilot run (10 configurations, all 100 senators)
python run_senator_extraction.py --mode pilot

# Priority configurations only (7 key configs)
python run_senator_extraction.py --mode priority

# Full matrix (80 configurations: 5 defenses × 4 prompt types × 2 ICL × 2 adaptive attacks)
python run_senator_extraction.py --mode matrix

# Limit to first N senators per config (useful for testing)
python run_senator_extraction.py --mode pilot --max_profiles 10

# Resume after interruption
python run_senator_extraction.py --mode pilot --resume

# Run configs in parallel using multiple API keys
python run_senator_extraction.py --mode matrix --parallel 4

# Filter to specific dimensions
python run_senator_extraction.py --mode matrix --defense_filter no,mask --prompt_filter direct --icl_filter 5

# Print commands without running
python run_senator_extraction.py --mode pilot --print_only
```

**Defenses:** `no`, `mask`, `replace_at_dot`, `pi_ci`, `hyperlink`  
**Prompt types:** `direct`, `pseudocode`, `contextual`, `persona`  
**ICL settings:** `0` (zero-shot), `5` (few-shot)  
**Adaptive attacks:** `no`, `yes`

`main.py` saves raw responses to `./result/<provider>_<model>/<dataset>_<defense>_<prompt>_<icl>_adaptive_attack_<adaptive>/all_raw_responses.npz`. It checkpoints every 10 profiles so interrupted runs can be resumed.

### Senator dataset — Baseline extractors

Run regex, keyword, spaCy, and BERT NER baselines:

```bash
python run_baselines.py
python run_baselines.py --output baseline_results.csv --skip_bert  # faster, skip BERT
```

### Summarizing results

After extraction runs complete, generate a results summary:

```bash
python summarize_results.py
# Outputs: results_summary.csv, results_table.md, results_table.tex, results_table_combined.md
```

Options:

```bash
python summarize_results.py \
  --result_dir ./result/groq_llama-3.1-8b-instant \
  --task_config ./configs/task_configs/senator.json \
  --baseline_csv ./baseline_results.csv \
  --output results_summary.csv
```

The combined table (`results_table_combined.md` / `results_table.tex`) merges LLM PIE results with baseline PIE results and ground-truth coverage, matching the format of Table 2 in Liu et al. (USENIX Security '25).

### Evaluating saved results (BERT score)

```bash
python evaluate.py \
  --provider groq \
  --model_name llama-3.1-8b-instant \
  --dataset senator \
  --defense no \
  --prompt_type direct \
  --icl_num 0 \
  --adaptive_attack no \
  --m2 bert-score
```

## Project structure

```
├── main.py                        # Core extraction script
├── run.py                         # Batch runner for original paper experiments
├── run_senator_extraction.py      # Senator extraction orchestration
├── run_baselines.py               # Regex/keyword/spaCy/BERT baselines
├── evaluate.py                    # Post-hoc evaluation (BERT score)
├── summarize_results.py           # Aggregate results into tables
├── configs/
│   ├── model_configs/             # Per-provider API key and param configs
│   │   ├── gpt_config.json
│   │   ├── gemini_config.json
│   │   ├── groq_config.json       # Groq (Llama 3.1-8b-instant)
│   │   └── llama_config.json
│   └── task_configs/
│       ├── synthetic.json
│       └── senator.json
├── data/
│   ├── senator/                   # Senator HTML profiles + labels
│   ├── synthetic/                 # Synthetic dataset
│   └── system_prompts/            # Prompt templates
├── external_data/ground_truth/    # Committee/religion ground truth
├── LLMPersonalInfoExtraction/     # Core library
│   ├── attacker/                  # Attack strategies
│   ├── defense/                   # Defense implementations
│   ├── evaluator/                 # Evaluation metrics
│   ├── models/                    # Model wrappers (GPT, Gemini, Groq, Llama)
│   ├── tasks/                     # Task and ICL managers
│   └── utils/                     # Parsing, config loading
├── result/                        # Extraction outputs (gitignored)
├── scripts/                       # Data setup utilities
└── PIE_environment.yml            # Conda environment
```
